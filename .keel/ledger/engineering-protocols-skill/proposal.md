# Proposal

## Problem / why
The upgrade brief identifies recurring engineering methods beyond lifecycle governance, but the repository has only control-plane skills and leaves protocol selection to rediscovery.

## Objective
Add one narrow routed repository skill that selects evidence-producing protocols for debugging/root cause, architecture investigation, dependency changes, migrations, security, performance, frontend runtime, test remediation, incidents, and release work.

## Non-goals
No mandatory workflow for unrelated tasks, generic personas, duplicated KEEL gates, external actions, or claims of empirical skill uplift without evaluation.

## Success evidence
The skill passes structural validation, has discriminating routing boundaries and failure/verification guidance, and is indexed in repository skill documentation.

## Open decisions
Protocol details remain concise in the skill; specialized provider/tool documentation stays in the repository domain docs and existing skills.
