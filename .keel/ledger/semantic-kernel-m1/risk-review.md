# Risk review

This M1 control-plane migration introduces future kernel semantics but deliberately does not connect them to existing writers, CLI routes, mission_v2, repository intelligence, evidence_graph, runtime/hooks, ledgers, or seal/anchor behavior. The main risks are creating a competing authority, accepting ambiguous input, unstable identity/digests, leaking host identity into portable intent, and compatibility regression. Mitigations are an isolated dependency-free module, strict authoritative decoding, explicit provenance and orthogonal enums, repository-relative resource validation without filesystem access, hostile tests, a required canonical check, and the complete unchanged legacy verification suite. No external or irreversible effect is requested. Integration is limited to the user-authorized local branch/PR workflow; no deployment or remote-system mutation beyond the requested PR is in scope.

Baseline verification exposed that P0's Windows absolute-path portability fixture fails on POSIX because `pathlib.Path.is_absolute()` follows host semantics. The compatibility bridge adds a lexical Windows-absolute check only; its existing fixture and the full suite constrain behavior.
